# Audit and Traceability

CyberClaw 强调执行后的可解释性与可追踪性。

## 为什么重要

在高风险系统里，平台不仅要能执行，还要回答：

- 谁发起了动作
- 动作经过了哪些治理判断
- 哪个 Connector / Capability 承担了真实执行
- 结果和产物如何被记录

## 在专业场景里通常要留下什么

只要进入真实场景，审计和追踪至少要回答这些问题：

- 代码审计 / PR 风险检查：
  审查对象是什么、引用了哪些上下文、输出了什么结论、是否生成了后续工单
- 告警分诊：
  告警来源是什么、拉取了哪些 trace / 日志 / 仓库上下文、最终分级是什么、通知了谁
- 安全事件处置：
  谁批准了后续动作、执行了哪些步骤、哪些动作只是建议、哪些动作真的落地
- 数据库变更：
  执行的是 `db.query`、`db.execute`、`db.transaction` 还是 `db.migrate`，影响范围和审批记录是什么
- Web3 高风险动作：
  钱包 / signer / 提案上下文是什么、策略判断如何做出、最终留下了哪些执行产物和追踪记录

## 读这页时的核心判断

如果一个 Agent 系统做了真实动作，却回答不了“谁批准、谁执行、执行了什么、留下什么证据”，那它就还不适合高风险环境。
