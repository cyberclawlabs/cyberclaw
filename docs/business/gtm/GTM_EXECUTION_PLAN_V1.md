# CyberClaw 推广执行方案（参考 OpenClaw / NanoClaw 路线）

更新时间：2026-03-18

## 1. 目标与结论

### 1.1 目标
在 90 天内完成 CyberClaw 的品牌占位、开发者增长与商业信任基础，形成可持续的生态增长飞轮。

### 1.2 核心结论
1. 需要提前注册核心社媒和品牌数字资产，避免后续被抢注。
2. 建议做商标布局，但采用“本国先申请 + 6 个月内国际延伸”的分阶段策略，不建议第一天就全球大规模申请。
3. 推广路线建议组合：
- 用 OpenClaw 的“上手体验 + 文档矩阵 + 多渠道触达”做增长。
- 用 NanoClaw 的“定位锋利 + 极简可改 + skill 驱动扩展”做产品心智。
- 用 NemoClaw 的“安全运行时 + 声明式策略 + 企业可治理”做 B2B 信任。

## 2. 参考路线提炼（可执行洞察）

### 2.1 OpenClaw 可借鉴点
1. 首页直接给“上手路径”（`onboard`）与文档入口，降低首用门槛。
2. 明确展示文档分区：Getting Started、FAQ、Showcase、Onboarding、Security。
3. 建立稳定/测试/开发发布通道，降低升级焦虑。
4. 社区入口前置（Discord）并配合展示页，形成用户反馈闭环。

### 2.2 NanoClaw 可借鉴点
1. 定位非常单点清晰：轻量、可理解、可定制、安全隔离。
2. 采用 fork-first 路线，让用户“复制后改造”，增强开发者参与感。
3. 强调 skills 扩展而不是主仓库持续膨胀，控制核心复杂度。
4. 通过 `/setup` 类体验降低复杂安装感知。

### 2.3 NemoClaw 可借鉴点
1. 把“安全”从口号落到可验证的运行时与策略生命周期。
2. 明确 alpha 状态与前置依赖，管理预期，减少误用。
3. 将运行时、网络、推理路由治理讲清楚，服务企业决策者。

## 3. 社媒与品牌资产注册清单（按优先级）

## 3.1 P0（48 小时内，必须）
1. 域名：`cyberclaw.com`、`cyberclaw.ai`、`cyberclaw.dev`。
2. 代码与开发者平台：GitHub Organization、npm 包名、PyPI 包名、crates.io 包名。
3. 核心社媒：X、LinkedIn Company Page、Discord Server、YouTube Channel。
4. 品牌邮箱体系：`hello@`、`security@`、`legal@`、`press@`。

## 3.2 P1（7 天内，建议）
1. 中文渠道：微信公众号、视频号、知乎机构号、B 站。
2. 开发者内容分发：Dev.to、Medium、Reddit（技术子版块）。
3. 产品展示入口：独立官网 Landing Page（包含安装、文档、路线图、案例）。

## 3.3 P2（30 天内，按资源）
1. Product Hunt 账号与首发素材。
2. Hacker News 发布素材准备（Show HN 格式）。
3. 合作伙伴渠道页（集成厂商/社区伙伴）。

## 4. 商标策略（是否要注册国际商标）

## 4.1 决策结论
1. 如果 6-12 个月内计划海外商业化、融资或签企业合同：需要国际商标布局。
2. 如果短期只做开源验证：先做本国申请，保留国际优先权窗口即可。

## 4.2 推荐路径
1. 第一步：本国申请（作为基础申请）。
2. 第二步：在 6 个月优先权期限内，按目标市场走马德里体系指定国家/地区。
3. 第三步：根据产品形态选择类别（通常至少评估 Nice 第 9 类和第 42 类，必要时再加第 35 类等）。

## 4.3 什么时候必须提速国际注册
1. 已有海外付费客户或代理商谈判。
2. 融资进入法务尽调阶段。
3. 出现同名/近似名抢注风险。

## 4.4 操作提醒
1. 先做近似检索再提交，减少驳回和重提成本。
2. 不同法域审查尺度不同，建议由商标律师执行正式检索与申请。
3. 以官方费用页面和计算器为准，不用二手报价作为决策依据。

## 5. 90 天执行节奏（结构化推进）

## 5.1 阶段 A：品牌占位与最小发布（Day 1-14）
1. 完成 P0/P1 账号注册与统一命名。
2. 发布官网首版与 GitHub 首页改版：
- 一句话定位。
- 1 分钟上手。
- 文档入口。
- 社区入口。
3. 发布第一批“样板技能包”（3-5 个高价值场景）。

阶段 KPI：
1. 关键账号命名一致率 100%。
2. 文档首条路径（安装到跑通）可在 10 分钟内完成。
3. 社区首批种子用户入群。

## 5.2 阶段 B：开发者增长（Day 15-45）
1. 固定周节奏内容：
- 每周 1 篇技术深度文。
- 每周 1 个演示视频或 GIF。
- 每周 1 个 skill 包发布。
2. 发起“fork + skill 贡献”活动，降低参与门槛。
3. 建立公开路线图与每周 changelog，增强透明度。

阶段 KPI：
1. 周活跃贡献者持续增长。
2. skill 包安装/复用数持续增长。
3. 文档到安装转化率持续提升。

## 5.3 阶段 C：信任与商业前置（Day 46-90）
1. 发布安全与治理白皮书（权限、审计、溯源、运行时隔离）。
2. 发布 2-3 个行业案例（R&D、DevOps、Security 场景）。
3. 建立“企业试点包”：
- 标准化部署说明。
- 合规与审计清单。
- 采购与法务 FAQ。

阶段 KPI：
1. 形成可复用案例资产。
2. 形成可销售的企业试点线索池。
3. 建立商标与品牌资产的法务可追踪台账。

## 6. 内容策略（避免“只发功能清单”）

内容支柱：
1. 上手速度：1 分钟跑通、10 分钟可用。
2. 可控安全：默认隔离、可审计、可追溯。
3. 生态扩展：Agent + Skill + Connector + Platform Plugin。
4. 真实场景：从告警研判、报告生成到自动化处置链路。

分发优先级：
1. GitHub + Docs（主阵地）。
2. X / LinkedIn（全球开发者和合作方）。
3. Discord（社区沉淀和反馈闭环）。
4. 中文社区（知乎/B 站/公众号）做增量扩散。

## 7. 组织与分工建议

1. Owner（产品/架构）：路线、定位、关键叙事。
2. DevRel：内容日历、直播演示、社区互动。
3. Engineering：样板技能包、演示工程、文档维护。
4. Security/Legal：商标、品牌保护、合规话术与对外声明。

## 8. 风险与应对

1. 风险：账号被抢注或命名不一致。
对应：P0 统一命名规范，集中注册与密码库管理。

2. 风险：过早铺太多渠道，内容供给不足。
对应：先守住 4 个核心阵地，再扩展。

3. 风险：只讲功能，不讲治理与信任。
对应：安全策略、审计链路、边界声明前置。

4. 风险：商标提交过晚导致出海阻塞。
对应：本国先申，6 个月内完成国际延伸决策。

## 9. 本周可执行清单（直接执行）

1. 完成 P0 资产注册并建立账号台账。
2. 输出统一品牌规范（命名、简介、链接、视觉）。
3. 改版 README 与官网首屏，补齐“安装-文档-社区-安全”四入口。
4. 准备第一批 3 个样板 skill（含演示视频）。
5. 启动商标近似检索，确定本国申请类别和申请主体。
